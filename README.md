# Nura on Xiaomi Redmi Note 10 5G (camellia)

Downstream Nura (postmarketOS) port for camellia, used as a headless Linux server:
charging, Wi-Fi, screen and touch for setup, USB OTG Ethernet optional.
Kept fully separate from the LineageOS 22.2 build.

## Layout

| What | Where |
|---|---|
| Kernel | `bjgo78/kernel_xiaomi_camellia`, branch `nura` (from `lineage-22.2` at `1576725`), own clone at `~/android/nura/kernel` |
| This repo | build script, Nura packages (`device-xiaomi-camellia`, `linux-xiaomi-camellia`, later firmware, WMT tool, power/thermal service) |
| Build output | `~/android/nura/KERNEL_OBJ`, `~/android/nura/dist` (not tracked) |
| pmbootstrap | its own work dir; packages are copied in from this repo |

The Lineage tree (`~/android/lineage`) is only read: clang r383902, GCC 4.9 binutils,
build-tools and `system/libufdt/utils/src/mkdtboimg.py`. Nothing from its `out/` is used.

Never commit partition backups (nvram, nvdata, nvcfg, persist, protect1/2, proinfo):
they contain IMEI, MAC addresses and calibration data.

## Build the kernel

    ~/android/nura/nura_xiaomi_camellia/build-nura-kernel.sh

Only `NURA_LOS` / `NURA_DIR` are read from the environment and make runs under `env -i`,
so a shell with Lineage's envsetup loaded (which exports `OUT`) is safe.
`TARGET_BUILD_VARIANT=userdebug` is passed explicitly, matching Lineage.

Result in `~/android/nura/dist`: `Image.gz`, `dtb.img` (DT table, one entry
`mediatek/mt6833.dtb`), the final config and the kernel commit.

## Kernel branch `nura`

- `camellia_nura.config`: fragment merged on top of `camellia_stock_defconfig`
  (devtmpfs, VT and fbcon, SysV IPC, USB NCM gadget, USB Ethernet for OTG,
  in-kernel fuel gauge, user namespaces, uevent helper).
- `MTK_BATTERY_KERNEL_GAUGE`: runs the in-kernel (recovery) gauge algorithm in normal boot,
  because the userspace `fuelgauged` does not exist outside Android. Default `n`.
- `STATIC_USERMODEHELPER` off: `ANDROID_DEFAULT_SETTING` used to select it (patched on
  this branch), which routed every usermode helper (uevent helper, poweroff/reboot) through
  the Android-only `/system_ext/bin/aee_core_forwarder`. `USER_NS` and `UEVENT_HELPER` on, as
  required by `pmbootstrap kconfig check`.
- `FW_LOADER_USER_HELPER_FALLBACK` stays on: `MEDIATEK_SOLUTION` selects it. The kernel still
  tries `/lib/firmware` directly first, but a file that is missing there makes it wait for a
  userspace helper (default 60 s per request). To do in the device package: write a short
  value to `/sys/class/firmware/timeout` early in boot.
- `vt: selection`: duplicate `set_selection()` from a 4.14.y merge removed (the file was
  never built while `VT` was off).

## Nura packages

`packages/` holds `device-xiaomi-camellia` (deviceinfo + the APKBUILD generated by
`pmbootstrap init`) and `linux-xiaomi-camellia`, which packages the prebuilt kernel from
`dist/` (pmbootstrap does not build it). After each kernel build:

    ~/android/nura/nura_xiaomi_camellia/pmaports-sync.sh

This copies the packages into pmbootstrap's pmaports (`device/downstream`, edge only),
adds `Image.gz`, `dtb.img` and the config, and updates the checksums there.

pmbootstrap: installed from git (PyPI releases are yanked), channel edge (downstream ports
exist only there), `pmbootstrap config systemd never` (OpenRC; the 4.14 kernel is too old
for current systemd).

deviceinfo notes: `deviceinfo_dtb` names the DT-table `dtb.img`, installed as
`/boot/dtbs/mediatek/mt6833-camellia-dtbtable.dtb` (boot-deploy requires `deviceinfo_dtb`
for header v2); rootfs sector size 4096 (UFS); USB networking uses NCM.

## Notes from Lineage (2026-10-28)

- Boot: header v2, `dtb.img` is a DT table (`androidboot.dtb_idx=0`). Keep
  `bootopt=64S3,32N2,64N2` in the cmdline. The dts bootargs carry `initcall_debug=1`;
  override with `initcall_debug=0`. Firmware loader falls back to `/lib/firmware`.
- Wi-Fi chain: `wmt_loader` (ioctls on `/dev/wmtdetect`) -> `wmt_launcher -p /vendor/firmware/ -o 1`
  (resident, answers patch search requests on `/dev/stpwmt`) -> NVRAM push:
  one `write()` of `WR-BUF:NVRAM` + the `WIFI` file (nvdata `APCFG/APRDEB/WIFI`, 2050 bytes)
  to `/dev/wmtWifi` (done by `wlan_assistant` on Android) -> `echo 1 > /dev/wmtWifi` gives `wlan0`.
- Charging control: `echo "0 1" > /proc/mtk_battery_cmd/current_cmd` stops charging but keeps
  the power path (tested: `Not charging`, +1.2 mA), `"0 0"` resumes. Not persistent.
  `battery/input_suspend` cuts input completely (runs on battery). `CURRENT_NOW` negative = charging.
- Thermal: Android's live policy equals the kernel defaults except `tzbattery`
  (Android: 60 C -> `mtktsbattery-sysrst`, 1 s polling; kernel: no trips). Restore with:

      echo "1 60000 0 mtktsbattery-sysrst 48000 0 no-cooler 46000 0 no-cooler 45000 0 no-cooler 44000 0 no-cooler 43000 0 no-cooler 42000 0 no-cooler 41000 0 no-cooler 40000 0 no-cooler 39000 0 no-cooler 1000" > /proc/driver/thermal/tzbattery

- Display: MTK DRM with fbdev on top of the LK framebuffer (`/dev/graphics/fb0` on Android).

## Bring-up log

- Boot 1 (`fastboot boot`): not supported by this LK; it falls back to recovery. Nura is flashed
  to `boot_b`; `boot_a`/`dtbo_a`/`vbmeta_a` hold Lineage's images for recovery and pstore.
- Boot 2: kernel runs, panics at 1.8 s in `fbcon_init` -> `cfb_imageblit`: `mtk_fbdev_probe`
  sets `info->screen_base = NULL`. fbcon disabled and `PMOS_NOSPLASH` added until the fbdev
  mapping (`mtk_gem->kvaddr`) is tested.
- Boot 3: initramfs could not find the rootfs subpartitions. On 4.14, `losetup -P
  --sector-size 4096` scans the loop device for partitions before the sector size is
  applied, and the kernel does not rescan. `blockdev --rereadpt /dev/loopN` makes
  `pmOS_boot`/`pmOS_root` appear. Fix planned: initramfs hook in the device package that
  rescans; propose the same one-liner upstream (`mount_subpartitions` in init_functions.sh).
  After the manual rescan, `pmos_continue_boot` led to a reboot: cause unknown, read pstore.

## Current phone layout

- `boot_b`: Nura boot.img (active slot). `userdata`: Nura rootfs image.
- `boot_a`, `dtbo_a`, `vbmeta_a`: Lineage images, only for recovery and pstore.
- `vbmeta_a`/`vbmeta_b`: flashed with verity and verification disabled.
- `fastboot boot` does not work on this LK (it falls back to recovery).

## Debugging

- USB networking (NCM): phone 172.16.42.1, host gets 172.16.42.2 by DHCP.
- Initramfs debug shell: `nc 172.16.42.1 23`.
- Kernel log after a crash: Vol Down + Power -> `fastboot set_active a` ->
  `fastboot reboot recovery` -> `adb shell cat /sys/fs/pstore/console-ramoops`.
  `fastboot set_active b` to go back.

## Rebuild from scratch (after a VM reset)

1. Lineage tree synced at `~/android/lineage` (only prebuilts and `mkdtboimg.py` are used).
2. `git clone -b nura git@github.com:bjgo78/kernel_xiaomi_camellia.git ~/android/nura/kernel`
   and clone this repo to `~/android/nura/nura_xiaomi_camellia`.
3. pmbootstrap from git: clone `https://gitlab.postmarketos.org/postmarketOS/pmbootstrap.git`
   into `~/android/nura/tools`, symlink `pmbootstrap.py` to `~/.local/bin/pmbootstrap`.
4. `./build-nura-kernel.sh`
5. `pmbootstrap init`: channel edge, vendor xiaomi, codename camellia, new downstream port
   (the generated files are replaced by the sync), UI console. Then
   `pmbootstrap config systemd never`.
6. `./pmaports-sync.sh`, `pmbootstrap build linux-xiaomi-camellia device-xiaomi-camellia`,
   `pmbootstrap install`, `pmbootstrap export`.
- Boot 4: loop rescan patch works (rootfs found, no debug shell). At the hand-over the
  initramfs removes its ACM serial and mass-storage functions while getty reopens ttyGS0;
  `gs_close()` then dereferenced a NULL port (Oops in tty_release <- tty_open). Patched
  u_serial; this was also the reboot after `pmos_continue_boot` in boot 3.
- USB IDs changed to 1d6b:0104: Windows ADB driver packs claim 18d1:d001 (Nura's default)
  as an ADB recovery interface, so the NCM network never appeared on Windows.
